# 0002: Fastlane builds and submits, on top of `expo prebuild`

- Status: Accepted
- Date: 2026-10-02

## Context

The app ships to Google Play and to the App Store in two flavors. Three ways
to build and submit were compared on four criteria.

|                                                 | License                                                                                                                  | Cost                                                                                                                          | Lock-in                                                                                                                                                                       | Two flavors                                                                                                                                                    |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Fastlane**                                    | MIT                                                                                                                      | Free tool. Runs on GitHub-hosted runners, which are free for public repositories, macOS included                              | Low. Hosted by the Mobile Native Foundation. Signing material stays in storage the team owns                                                                                  | One prebuild per flavor, each in a clean workspace, then the same lanes with the flavor as a parameter. Managed Google Play private apps have built-in actions |
| **EAS Build and Submit**                        | The CLI is MIT. The build engine is Business Source License 1.1, which its own text says "is not an Open Source license" | Free plan: 15 Android and 15 iOS builds a month on a low-priority queue. Then 19 or 199 USD a month plus 1 to 4 USD per build | High. An Expo account is required for hosted builds, for `eas build --local` and for `eas submit`. Credentials and the remote version counter live on Expo servers by default | Build profiles in `eas.json` set `APP_VARIANT`                                                                                                                 |
| **Gradle and `xcodebuild` plus the store APIs** | Expo CLI is MIT. Apple's tools are proprietary and ship with Xcode                                                       | Free on public-repository runners                                                                                             | Lowest tool lock-in                                                                                                                                                           | Possible, with every script written here                                                                                                                       |

What is open and what is paid in EAS: `eas-cli`, the Expo SDK and the Expo
CLI are MIT and free. The hosted services (Build, Submit, Update, Workflows)
are where pricing applies, and the code that `eas build --local` executes is
under the Business Source License until its change date, 2029-10-01.

## Decision

Use Fastlane, driving Gradle and `xcodebuild` on native projects generated by
`npx expo prebuild`, inside GitHub Actions.

- `APP_VARIANT=<flavor> npx expo prebuild --clean` generates `android/` and
  `ios/` for one flavor from `app.config.ts`. Expo documents this without
  EAS, and notes that switching variants means regenerating the native
  folders. Each flavor is therefore built in its own job, in a clean
  workspace, and a lane never builds two flavors from one checkout.
- Fastlane `gradle` and `build_app` build, `upload_to_play_store`,
  `upload_to_testflight` and `upload_to_app_store` submit, and `match` keeps
  the iOS signing identities in private storage.
- App Store Connect is reached with an API key. Google Play is reached with
  a service account or workload identity federation.

**Discarded: EAS Build and Submit.** Its build engine is not open source and
every path through it, the local one included, requires an Expo account.

**Discarded: Gradle and `xcodebuild` with direct store API calls.** It
rewrites upload, track promotion and signing sync that Fastlane already
maintains, and Apple's command-line upload path is in transition
(`altool --upload-app` is marked deprecated in favour of `--upload-package`).

## Consequences

- The repository carries a `Gemfile` and Ruby in CI.
- Building and signing are separate jobs (ADR 0008). The build job compiles
  an unsigned Android bundle and an unsigned iOS archive. The upload job
  signs and submits them without running repository code. Generated folders
  are never edited by hand, because `prebuild --clean` discards them.
- The first Android upload of each package is manual. The Play Developer API
  only changes an app "that has at least one APK uploaded".
- EAS stays available to an adopter who prefers it. Nothing here blocks
  adding `eas.json` later.
- On a private repository the macOS runner is billed per minute, about ten
  times the Linux rate. This repository is public.
